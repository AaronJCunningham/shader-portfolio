# WebGPU Header Scene Ideas

Direction: keep the header abstract, futuristic, and visually premium, but make each scene feel like a different state of the same technical system.

## Scene Progression

1. Scene 1: object
   - Stable spherical particle organism.
   - Points undulate, breathe, and move toward/away from the mouse.
   - This remains close to the original header's first scene.

2. Scene 2: field
   - Magnetic intelligence field.
   - Particles organize into curved field lines, orbital bands, pressure waves, and cursor-driven bending.
   - Mouse movement should visibly distort the field so users immediately understand the header is interactive.

3. Scene 3: signal
   - Luminous signal fabric.
   - Ribbon or strand forms that braid, fold, interfere, and ripple when the pointer passes nearby.
   - Should feel like an oscilloscope, neural signal, and premium interface language at once.

4. Scene 4: architecture
   - Neural topography / system map.
   - Grid, nodes, paths, pulses, and vertical structures that respond to scanning mouse movement.
   - Should feel like a city, circuit board, terrain model, and data system without becoming literal.

## Why WebGPU + TSL

- TSL keeps shader logic modular and closer to TypeScript, which makes these scenes easier to evolve than raw GLSL strings.
- WebGPU gives us a cleaner path toward larger particle counts, storage-buffer style simulation, compute-driven motion, and richer post-processing.
- The old WebGL header should remain as fallback for unsupported browsers or WebGPU runtime failure.
